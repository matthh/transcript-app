## SECURITY

### Critical

#### SC-1 · `PUT` and `DELETE /api/transcripts/[episode]` are unauthenticated
**File:** `src/app/api/transcripts/[episode]/route.ts`
**Finding:** Any internet client can overwrite or delete production transcripts
in Vercel Blob storage without authentication, session, or IP guard. An
attacker who enumerates episode numbers can wipe the entire transcript corpus.
**ARCHITECTURE.md ref:** T-19
**Recommended fix:** Gate behind the bearer-password pattern used by PodReview
(`src/lib/podreview-auth.ts`), or require a `CRON_SECRET` / admin token.
**Status:** Open — upstream issue, not fixable in this fork.

#### SC-2 · `POST /api/transcript-rename` is unauthenticated
**File:** `src/app/api/transcript-rename/route.ts`
**Finding:** Any caller can rename (move) transcripts in Blob storage without
authentication, swapping episode slots and corrupting the transcript index.
**ARCHITECTURE.md ref:** T-20
**Recommended fix:** Same bearer-password guard as SC-1.
**Status:** Open — upstream issue, not fixable in this fork.

#### SC-3 · `POST /api/rebuild` triggers GitHub Actions without auth
**File:** `src/app/api/rebuild/route.ts`
**Finding:** No authentication guard. Any caller who discovers the URL can
trigger arbitrary `ingest-episode.yml` workflow runs against the upstream repo
using the stored `GITHUB_PAT`, consuming CI minutes and potentially corrupting
the search index.
**ARCHITECTURE.md ref:** T-3
**Recommended fix:** Check a `CRON_SECRET` or admin bearer token before calling
the GitHub Actions dispatch API.
**Status:** Open — upstream issue, not fixable in this fork.

#### SC-4 · Retired model IDs cause silent production failures
**Files:** `src/lib/routing-policy.ts` (lines 45, 109),
`src/lib/search-tuning.ts` (line 23)
**Finding:**
- `DEEP_SYNTHESIS_MODEL = 'claude-sonnet-4-20250514'` — used for all deep
  answer synthesis and agent search — is past its announced retirement date.
  Retired models return HTTP 404; every non-trivial search query silently fails.
- `AGENT_SEARCH_MODEL = 'claude-sonnet-4-20250514'` — same retirement risk.
- `getSearchTuning('fast')` defaults to `claude-3-haiku-20240307` when
  `INTERPRETIVE_FAST_MODEL` is unset. Claude 3 Haiku is retired.
**ARCHITECTURE.md ref:** T-23, T-16
**Recommended fix:** Migrate both constants to a current model ID (e.g.
`claude-sonnet-4-5`) and set the fast-variant default to
`claude-haiku-4-5-20251001`. Verify with `npm run check:models`.
**Status:** Open — upstream issue, not fixable in this fork.

### High

#### SH-1 · AssemblyAI webhook has no signature verification
**File:** `src/app/api/transcribe/webhook/route.ts` (line 22)
**Finding:** The route accepts any POST that supplies a known `transcript_id`.
An attacker who enumerates job IDs can inject a fake "completed" payload,
causing `saveTranscript()` and `saveRawTranscript()` to overwrite Blob storage
with attacker-controlled content.
**ARCHITECTURE.md ref:** T-6
**Recommended fix:** Validate the AssemblyAI webhook HMAC-SHA256 signature
before processing the body.
**Status:** Open — upstream issue, not fixable in this fork.

#### SH-2 · HTML injection in email templates
**Files:** `src/app/api/feedback/route.ts` (lines 145–176),
`src/app/api/transcription-error/route.ts` (lines 104–162)
**Finding:** User-supplied fields (`entry.name`, `entry.query`, `entry.answer`,
`entry.comment`, `report.episodeTitle`, `report.selectedText`,
`report.correctedText`, `report.originalText`, `report.reporterName`) are
interpolated directly into HTML email strings without escaping. Crafted input
containing `<script>` or inline style tags will render in the notification email.
**ARCHITECTURE.md ref:** T-14, T-21
**Recommended fix:** HTML-escape all user-supplied values before interpolation
(replace `<`, `>`, `&`, `"`, `'` with their HTML entities).
**Status:** Open — upstream issue, not fixable in this fork.

#### SH-3 · User data and query logs stored as public Vercel Blobs
**Files:** `src/lib/query-logger.ts` (line 74), `src/app/api/feedback/route.ts`
(line 89), `src/app/api/cleanup-feedback/route.ts`,
`src/app/api/eval/feedback/route.ts`
**Finding:** All query logs and user feedback entries are written with
`access: 'public'`. Anyone with a predictable blob pathname
(`query-log/YYYY-MM/ql_*.json`, `feedback-log/YYYY-MM/fb_*.json`) can read
full user query text, names, and answer content.
**ARCHITECTURE.md ref:** T-8, T-10
**Recommended fix:** Set `access: 'private'` and serve logs only via
server-side authenticated fetch.
**Status:** Open — upstream issue, not fixable in this fork.

#### SH-4 · `POST /api/debug` is unauthenticated and leaks internals
**File:** `src/app/api/debug/route.ts`
**Finding:** Runs a live LLM query classification and returns full internal
metadata and classifier state to any caller. Contains a hardcoded
`filmFilter = 'close encounters'` debugging artifact. Incurs Anthropic API cost
per request with no rate limiting.
**ARCHITECTURE.md ref:** T-2
**Recommended fix:** Add a bearer-token guard or remove the route from
production builds.
**Status:** Open — upstream issue, not fixable in this fork.

### Medium

#### SM-1 · `POST /api/eval/generate` fires uncapped LLM calls without auth
**File:** `src/app/api/eval/generate/route.ts`
**Finding:** No authentication, rate limit, or cost cap. Any internet caller can
drive unbounded Anthropic API spend.
**ARCHITECTURE.md ref:** T-24
**Recommended fix:** Protect behind `CRON_SECRET` or the `PODREVIEW_PASSWORD`
bearer pattern.
**Status:** Open — upstream issue, not fixable in this fork.

#### SM-2 · Analytics and eval result endpoints are unauthenticated
**Files:** `src/app/api/analytics/use-cases/route.ts`,
`src/app/api/eval/results/route.ts`
**Finding:** Both endpoints list structured data from query logs — including
full query text, use-case tags, and per-query ratings — with no auth check.
**ARCHITECTURE.md ref:** T-25, T-26
**Recommended fix:** Add a `Bearer <ANALYTICS_TOKEN>` check via an env var
before returning any log data.
**Status:** Open — upstream issue, not fixable in this fork.

#### SM-3 · PodReview password uses non-timing-safe string comparison
**File:** `src/lib/podreview-auth.ts`
**Finding:** Auth uses `=== password` (JavaScript string equality, not
constant-time). Susceptible to timing-based enumeration. No brute-force
protection.
**ARCHITECTURE.md ref:** T-4
**Recommended fix:** Use `crypto.timingSafeEqual()` on Buffer representations
of the two strings.
**Status:** Open — upstream issue, not fixable in this fork.

#### SM-4 · In-memory rate limit on `/api/external/search` is per-Lambda-instance
**File:** `src/lib/external-rate-limit.ts`
**Finding:** Rate counters reset when a Lambda instance is recycled. Under a
multi-instance Vercel region, a single key can exceed limits by a factor equal
to the number of active instances.
**ARCHITECTURE.md ref:** T-1
**Recommended fix:** Replace in-memory counters with Upstash Redis or Vercel KV.
**Status:** Open — upstream issue, not fixable in this fork.

#### SM-5 · TMDB API key sent as query parameter (server-side)
**Files:** `src/app/api/tilda/route.ts`, `src/app/api/kev/route.ts`,
`src/app/api/podreview/tmdb-search/route.ts`
**Finding:** `api_key` forwarded as a query string parameter in server-to-server
requests. The key appears in Vercel function logs, TMDB access logs, and any
proxy traces.
**ARCHITECTURE.md ref:** T-7
**Recommended fix:** Switch to TMDB bearer token auth
(`Authorization: Bearer <token>`).
**Status:** Open — upstream issue, not fixable in this fork.

## PERFORMANCE

### High

#### PH-1 · `/api/transcripts` and `/api/speakers` do O(N) serial Blob fetches
**Files:** `src/app/api/transcripts/route.ts` (lines 12–30),
`src/app/api/speakers/route.ts`
**Finding:** Both routes load every transcript from Vercel Blob one at a time
in a serial loop with no parallelisation and no TTL cache. With 300+ transcripts,
each request incurs 300+ sequential network round-trips.
**ARCHITECTURE.md ref:** T-22, T-15
**Recommended fix:** Parallelise with `Promise.all()` and add an in-memory TTL
cache (e.g. 60 s) keyed to build ID or a short expiry.
**Status:** Open — upstream issue, not fixable in this fork.

#### PH-2 · Agent search loads all 300+ transcripts into Lambda memory on first call
**File:** `src/lib/agent-search.ts`
**Finding:** The agent loads every transcript from Blob on the first agent
request, holding all of them in a module-level cache. This causes cold-start
latency spikes and high memory pressure; the cache grows unboundedly across the
Lambda's lifetime.
**ARCHITECTURE.md ref:** T-18
**Recommended fix:** Lazy-load individual transcripts by episode number; add an
LRU eviction policy.
**Status:** Open — upstream issue, not fixable in this fork.

### Medium

#### PM-1 · Vector store, BM25 index, and playlist data cached indefinitely
**Files:** `src/lib/vectorstore.ts`, `src/lib/bm25-loader.ts`,
`src/app/api/playlist/route.ts`
**Finding:** All three use module-level caches with no TTL or invalidation
signal. A long-lived warm Lambda instance will serve stale search data after a
re-ingest or playlist update without a redeploy.
**ARCHITECTURE.md ref:** T-9, T-17
**Recommended fix:** Add an etag or timestamp check against Blob metadata on
each request, refreshing the in-memory copy when the Blob has changed.
**Status:** Open — upstream issue, not fixable in this fork.

## MAINTAINABILITY

### Medium

#### MM-1 · PodReview submit/update-pdc split is confusing
**Files:** `src/app/api/podreview/submit/route.ts`,
`src/app/api/podreview/update-pdc/route.ts`
**Finding:** `POST /api/podreview/submit` only logs to console and returns the
formatted row without writing to Google Sheets. The actual sheet write is in
`POST /api/podreview/update-pdc`. No UI distinction exists between the two
routes, making it unclear which one actually persists data.
**ARCHITECTURE.md ref:** T-5
**Recommended fix:** Consolidate into one endpoint or rename clearly (e.g.
`/api/podreview/preview` vs. `/api/podreview/submit`).
**Status:** Open — upstream issue, not fixable in this fork.

#### MM-2 · Google Sheets ID and GitHub repo name hardcoded as string literals
**Files:** `src/app/api/podreview/update-pdc/route.ts`,
`src/app/api/rebuild/route.ts`
**Finding:** `SHEET_ID = '1RbtWP966CxA57PatyMcbJ6_ylg9tmCvDSLNxjmQ4bvk'` and
`GITHUB_REPO = 'jbennygold/transcript-app'` are plain string literals. Renaming
the repo or moving the sheet silently breaks both routes.
**ARCHITECTURE.md ref:** T-11, T-12
**Recommended fix:** Move both to env vars (`PODREVIEW_SHEET_ID`, `GITHUB_REPO`).
**Status:** Open — upstream issue, not fixable in this fork.

#### MM-3 · Anthropic client instantiated outside the singleton in multiple files
**Files:** `src/app/api/cleanup-transcript/route.ts`,
`src/app/api/detect-samples/route.ts`, `src/lib/share-summary.ts`
**Finding:** These files call `new Anthropic()` directly rather than
`getAnthropic()` from `src/lib/claude.ts`, creating redundant client instances
per Lambda cold start.
**ARCHITECTURE.md ref:** T-13
**Recommended fix:** Import and use `getAnthropic()` everywhere.
**Status:** Open — upstream issue, not fixable in this fork.

### Low

#### ML-1 · ChromaDB dependency retained but unused in production
**File:** `package.json` (`chromadb` dependency), `src/lib/chroma.ts`
**Finding:** The `chromadb` package is still listed in `dependencies` and
`src/lib/chroma.ts` still exists, but ChromaDB has been superseded by the
Vercel Blob vector store. The dead dependency adds bundle and install weight.
**ARCHITECTURE.md ref:** deprecated paths section
**Recommended fix:** Remove `chromadb` from `dependencies` and delete
`src/lib/chroma.ts`.
**Status:** Open — upstream issue, not fixable in this fork.

#### ML-2 · Stale eval and A/B log files committed to the repository
**Files:** `data/eval-baseline-2026-02-21.json`, `data/eval-post-*.json`
(six files), `ab-intents-2026-02-12.log`
**Finding:** Historical eval snapshots and an A/B log from February 2026 are
committed to the repo root and `data/`. These grow the repo and may contain
user query text.
**Recommended fix:** Move to Vercel Blob storage; add `.gitignore` entries for
`ab-*.log` and `data/eval-*.json`.
**Status:** Open — upstream issue, not fixable in this fork.

#### ML-3 · `data/episode-metadata.json` is stale and no longer the live source
**File:** `data/episode-metadata.json`
**Finding:** The live metadata source has moved to `src/lib/metadata-data.ts`
(TypeScript, synced by CI). The JSON file in `data/` is not read by any current
code path and may mislead future contributors.
**ARCHITECTURE.md ref:** deprecated paths section
**Recommended fix:** Delete `data/episode-metadata.json` and add a comment in
`metadata-data.ts` noting the migration.
**Status:** Open — upstream issue, not fixable in this fork.
