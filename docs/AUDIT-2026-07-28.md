## Critical

### C-1 · `/api/rebuild` is unauthenticated — carry-over from 2026-07-14
**File:** `src/app/api/rebuild/route.ts`
**Status:** **Not fixed upstream.** Any internet-accessible caller can trigger a full index
rebuild, exhausting embedding quotas (Anthropic / OpenAI).
**Recommended fix (upstream):** Gate behind `CRON_SECRET` or an admin session check.

### C-2 · AssemblyAI webhook has no signature verification — carry-over from 2026-07-14
**File:** `src/app/api/transcribe/webhook/route.ts`
**Status:** **Not fixed upstream.** No `x-assemblyai-signature` header verification; any
caller who can guess a transcript ID can inject fake transcripts into Blob storage.
**Recommended fix (upstream):** Verify the HMAC-SHA256 signature using AssemblyAI's webhook
secret before processing.

### C-3 · `PUT /api/transcripts/[episode]` is unauthenticated — NEW
**File:** `src/app/api/transcripts/[episode]/route.ts` (lines 43–78)
**Finding:** The PUT handler writes arbitrary JSON to `transcripts/episode_NNN.json` in Vercel
Blob with no authentication. Any internet caller can overwrite the text of any production
transcript, poisoning the search index and the transcript review tool.
**Recommended fix (upstream):** Require a session token or shared secret (e.g. compare
`Authorization` against `PODREVIEW_PASSWORD` or a dedicated `TRANSCRIPT_WRITE_TOKEN`) before
calling `saveBlobTranscript`.

### C-4 · `DELETE /api/transcripts/[episode]` and `POST /api/transcript-rename` are
unauthenticated — NEW
**Files:** `src/app/api/transcripts/[episode]/route.ts` (lines 80–149);
`src/app/api/transcript-rename/route.ts`
**Finding:** The DELETE handler restores or fully deletes a transcript from Blob with no auth.
`/api/transcript-rename` moves a transcript from one episode slot to another with no auth.
Either operation can corrupt the transcript corpus in production without leaving a useful audit
trail.
**Recommended fix (upstream):** Apply the same auth guard recommended for C-3 to both
endpoints.

### C-5 · Deep-synthesis and agent-search model IDs may be approaching retirement — NEW
**File:** `src/lib/routing-policy.ts` (lines 45, 109)
**Finding:** `DEEP_SYNTHESIS_MODEL = 'claude-sonnet-4-20250514'` and
`AGENT_SEARCH_MODEL = 'claude-sonnet-4-20250514'` are date-stamped model IDs. Anthropic
retires dated model IDs without prior warning; when the endpoint returns 404 the failure is
silent from a user perspective (the search returns an error rather than a visible "model
retired" message). A sibling project (`escape-hatch-explore`) was observed to silently break
in production when this same model ID aged out.
**Recommended fix (upstream):** Verify the model IDs are still live using the models list API
endpoint (no credits consumed). Add a CI step — equivalent to `npm run check:models` in the
sibling project — to catch retirements before they reach production.

### H-3 · HTML injection in `/api/feedback` email template — NEW
**File:** `src/app/api/feedback/route.ts` (lines 143–181)
**Finding:** `entry.name`, `entry.query`, `entry.answer`, and `entry.comment` are
interpolated directly into the HTML notification email with template-literal syntax and no
HTML escaping. A user submitting feedback with HTML tags in their query or comment field will
have those tags rendered in the email. This is the same vulnerability pattern as T-14
(`/api/transcription-error`).
**Recommended fix (upstream):** Escape all user-supplied strings before interpolating into
HTML. A simple helper: `function escapeHtml(s: string): string { return s.replace(/&/g,'&amp;').replace(/</g,'&lt;').replace(/>/g,'&gt;').replace(/"/g,'&quot;'); }`.

## Medium

### M-1 · No rate limiting on search or rebuild endpoints — carry-over from 2026-07-14
**Status:** **Not fixed upstream.**

### M-2 · Transcript upload lacks server-side size validation — carry-over from 2026-07-14
**Status:** **Not fixed upstream.**

### M-3 · No error boundary for malformed transcript rendering — carry-over from 2026-07-14
**Status:** **Not fixed upstream.**

### M-4 · `GET /api/transcripts` O(N) serial Blob-fetch waterfall — NEW
**File:** `src/app/api/transcripts/route.ts` (lines 13–28)
**Finding:** The transcript list endpoint iterates through all blob transcripts in a serial
`for` loop, calling `loadBlobTranscript` and `audioExists` one at a time with no
parallelisation and no cache. At 300+ transcripts this produces a very long response time on
every cold list request. Identical performance pattern to T-15 (`/api/speakers`).
**Recommended fix (upstream):** Replace the serial loop with `Promise.all`, or store
transcript metadata separately so the list endpoint doesn't need to fetch every transcript
body.

### M-5 · `GET /api/cleanup-feedback` and `POST /api/cleanup-feedback` are unauthenticated
— NEW
**File:** `src/app/api/cleanup-feedback/route.ts`
**Finding:** The GET endpoint returns all AI-cleanup accept/reject decisions (including
transcript text excerpts) with no authentication. The POST endpoint lets any caller log
arbitrary cleanup decisions under any episode number. Neither has an auth guard.
**Recommended fix (upstream):** Protect the GET endpoint with the same bearer-token pattern
used by `/api/feedback` (optional `FEEDBACK_API_TOKEN`). Protect the POST endpoint with a
transcript write token.
