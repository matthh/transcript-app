# transcript-app — Audit 2026-08-04

> **Fork policy**: This repo is a fork of `jbennygold/transcript-app`. We do not maintain
> application code here. This audit documents findings for upstream awareness; no source-code
> changes are made in this fork.

## What changed since 2026-07-28

No code changes. The last commit (`3f1fbc1`) was the 2026-07-28 audit doc. All previously
identified findings remain open. This cycle adds three new findings (C-6, M-6, L-4) and
escalates the model-retirement risk (C-5): `claude-sonnet-4-20250514` is confirmed retired
in a sibling project (escape-hatch-explore) and is almost certainly failing in this app's
production deep-synthesis and agent-search paths as well.

## Critical

### C-1 · `/api/rebuild` is unauthenticated — carry-over from 2026-07-14
**File:** `src/app/api/rebuild/route.ts`
**Status:** Not fixed upstream. Any internet-accessible caller can trigger a full index
rebuild, exhausting embedding quotas (Anthropic / OpenAI).
**Recommended fix (upstream):** Gate behind `CRON_SECRET` or an admin session check.

### C-2 · AssemblyAI webhook has no signature verification — carry-over from 2026-07-14
**File:** `src/app/api/transcribe/webhook/route.ts`
**Status:** Not fixed upstream. No `x-assemblyai-signature` header verification; any caller
who can guess a transcript ID can inject fake "completed" payloads into Blob storage,
overwriting production transcripts.
**Recommended fix (upstream):** Verify the HMAC-SHA256 signature using AssemblyAI's webhook
secret before processing.

### C-3 · `PUT /api/transcripts/[episode]` is unauthenticated — carry-over from 2026-07-28
**File:** `src/app/api/transcripts/[episode]/route.ts` (lines 43–78)
**Status:** Not fixed upstream. Any internet caller can overwrite any production transcript
in Vercel Blob, poisoning the search index.
**Recommended fix (upstream):** Require a session token or shared secret before calling
`saveBlobTranscript`.

### C-4 · `DELETE /api/transcripts/[episode]` and `POST /api/transcript-rename` are
unauthenticated — carry-over from 2026-07-28
**Files:** `src/app/api/transcripts/[episode]/route.ts` (lines 80–149);
`src/app/api/transcript-rename/route.ts`
**Status:** Not fixed upstream. DELETE and rename operations on production transcripts
are fully unauthenticated.
**Recommended fix (upstream):** Same auth guard as C-3.

### C-5 · Deep-synthesis and agent-search model IDs confirmed approaching or past
retirement — escalated from 2026-07-28
**File:** `src/lib/routing-policy.ts` (lines 45, 109)
**Finding:** `DEEP_SYNTHESIS_MODEL` and `AGENT_SEARCH_MODEL` are both set to
`'claude-sonnet-4-20250514'`. A sibling project (`escape-hatch-explore`) observed this
exact model ID silently 404-ing in production "a month past its retirement" — the deployment
continued to run while deep synthesis and agent search both returned errors. Given that model
IDs in the `claude-*-YYYYMMDD` scheme are retired on Anthropic's schedule without prior
warning, this app's production instance is likely already failing for any search that routes
to `DEEP_SYNTHESIS_MODEL` or `AGENT_SEARCH_MODEL`. `claude-3-haiku-20240307` referenced in
`search-tuning.ts` (T-16) is an earlier-generation model with an even longer retirement
exposure window.
**Recommended fix (upstream):** Run `npm run check:models` or call
`https://api.anthropic.com/v1/models` to confirm which IDs are still live, then migrate to
currently-supported model IDs. Add a CI step on the weekly `new-episodes.yml` workflow to
catch future retirements before they reach production.

### C-6 · `POST /api/eval/generate` is unauthenticated — NEW
**File:** `src/app/api/eval/generate/route.ts`
**Finding:** The eval question-generation endpoint fires a Claude Haiku LLM call on every
request — loading the vector store, sampling transcript chunks, and calling the Anthropic API —
with no authentication, rate limiting, or cost cap. Any internet caller who discovers the
endpoint can spam it, exhausting Anthropic API credits. The vector-store load on a cold
instance also incurs Blob fetch cost per request.
**Recommended fix (upstream):** Protect behind the `PODREVIEW_PASSWORD` bearer pattern or
a dedicated `EVAL_ADMIN_TOKEN` env var. Add a per-IP rate limit consistent with the external
search endpoint pattern (`src/lib/external-rate-limit.ts`).

### M-6 · `GET /api/analytics/use-cases` is unauthenticated — NEW
**File:** `src/app/api/analytics/use-cases/route.ts`
**Finding:** The analytics endpoint fetches and aggregates full query-log entries from Vercel
Blob — including user query text, use-case tags, routing path, and rating — with no
authentication. The drill-down view (`?useCase=UC-N`) also returns the raw query string for
every matched log entry. This compounds T-10 (query logs are public Blobs): even if Blob URLs
were made private, this endpoint re-exposes the same data through a convenient structured API.
**Recommended fix (upstream):** Add a bearer-token check (env var `ANALYTICS_ADMIN_TOKEN`)
before executing any Blob list or fetch operation.
